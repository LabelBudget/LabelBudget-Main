## 1. 파일 구조

9,982행 × 26열. 핵심 컬럼은 다음과 같다.

| 컬럼 | 내용 | 활용 |
|---|---|---|

| `Solubility` | logS, log10(mol/L) | 라벨 |
| `InChIKey` | 식별자 | 중복 판정 |
| **`SD`** | **출처 간 측정 표준편차** | **노이즈 하한 추정 ★** |

> `SD`·`Ocurrences`·`Group`은 기존 스펙에서 고려하지 않았던 컬럼이다.

## 4. ★ 치명적 발견 — 염 제거가 라벨을 파괴한다

원본에는 중복이 **없었다**(InChIKey 9,982개 전부 고유). 그런데 염 제거를 적용하자 중복이 **새로 생겼다.**

| 항목 | 값 |
|---|---|
| 표준화 통과 | 9,611건 |
| 고유 InChIKey | 9,276건 |
| **새로 생긴 중복 그룹** | **191개** |
| 관련 행 | 526건 |
| 병합 시 손실 | 원본 9,982 → 9,276 (**706건 감소**) |

### 중복 그룹의 라벨 불일치

| 통계 | spread (logS) |
|---|---|
| 평균 | 1.814 |
| 중앙값 | 1.111 |
| 최대 | **9.481** |

| 임계값 | 그룹 수 |
|---|---:|
| spread > 0.5 | 132 |
| spread > 1.0 | 102 |
| spread > 2.0 | 62 |
| spread > 3.0 | 42 |

### 왜 이런 일이 생기는가

**짝이온이 용해도를 결정한다.** 염 제거는 그 정보를 지운다.

실제 예시:

```
spread = 9.12
  4-hydroxybenzenesulfonic acid        logS =  0.76   (유리산)
  sodium 4-hydroxybenzene-1-sulfonate  logS = -8.36   (소듐염)
  → 염 제거 후 둘 다 같은 분자가 된다
```

```
spread = 6.50  (탄산염 21종이 전부 "carbonate" 하나로 병합)
  disodium carbonate    logS =  0.58   (잘 녹음)
  dipotassium carbonate logS =  0.95
  calcium carbonate     logS = -3.78   (거의 안 녹음)
  lead carbonate        logS = -5.55
```

```
spread = 9.48  (2-ethylhexanoate 염 10종 + 유리산 1종)
  sodium 2-ethylhexanoate      logS =  0.78
  2-ethylhexanoic acid, Zr salt logS = -8.70
```

탄산나트륨은 물에 잘 녹고 탄산칼슘은 거의 녹지 않는다. 이것을 같은 분자로 처리하면, 모델에게 **같은 입력에 서로 다른 정답을 주는 것**이 된다. 이는 노이즈가 아니라 **큐레이션이 만들어낸 오류**다.

> 기존 스펙은 `tolerance=1.0`으로 이 충돌을 중앙값으로 조용히 병합하도록 돼 있었다.
> **그렇게 하면 102개 그룹의 화학적 구분이 소리 없이 사라진다. 잘못된 설계였다.**

## 5. 정책 B 검증 — 염을 제거하지 않고 거부

다단편 입력을 **병합하지 않고 거부**하도록 바꿔 다시 측정했다.

| 지표 | 정책 A (염 제거) | **정책 B (다단편 거부)** |
|---|---:|---:|
| 통과 건수 | 9,611 | 8,746 |
| 고유 InChIKey | 9,276 | **8,740** |
| 중복 그룹 | 191 | **6** |
| spread > 1.0 그룹 | 102 | **1** |
| 잔존 spread 중앙값 | 1.111 | **0.062** |

약 900건(9%)을 잃는 대신, **인공 충돌이 191 → 6 그룹으로 사라진다.** 남은 6그룹의 spread 중앙값 0.062는 측정 오차 수준이다.

### 권고

| 과제 | 정책 |
|---|---|
| **용해도 (회귀)** | **정책 B.** 다단편 입력 거부. 염 제거 금지 |
| 독성 (Tox21 분류) | 정책 A 허용 가능. 활성은 보통 모분자가 결정하므로 염 제거가 통례. 단 같은 감사를 Tox21에도 돌려 확인할 것 |

이 차이를 리포트에 적는 것 자체가 도메인 이해의 증거가 된다.
*"용해도는 짝이온에 의존하므로 다른 과제와 표준화 정책을 달리해야 한다"* 는 문장을 근거 수치와 함께 쓸 수 있다.

## 6. 측정 노이즈 하한 (LIMITATIONS.md용 근거)

`SD` 컬럼이 출처 간 측정 불일치를 직접 알려준다.

| 항목 | 값 |
|---|---:|
| SD = 0 (단일 출처 또는 완전 일치) | 7,746 (77.6%) |
| SD > 0 | 2,236 |
| SD > 0 의 평균 | **0.301** |
| SD > 0 의 중앙값 | 0.132 |
| SD > 0 의 최대 | 3.870 |
| SD > 0.5 | 418 |
| SD > 1.0 | 155 |
| SD > 2.0 | 17 |

`Ocurrences` 분포: 1개 출처 7,746 / 2개 1,417 / 3개 494 / 4개 177 / 5개 81 / 6개 이상 67 (최대 38개 출처)

### 쓸 수 있는 문장

> 복수 출처에서 측정된 2,236개 분자의 출처 간 표준편차는 평균 0.301 logS다.
> 따라서 이 데이터에서 RMSE 0.3 미만은 측정 노이즈 구간이며, 그 이하의 개선은
> 실질적 의미가 없다.

이 한 문장이 **"자기 결과의 천장을 아는 사람"** 이라는 신호를 준다.

## 7. ★ 추가 차별점 — `Group` 컬럼 층화 평가

AqSolDB는 자체 신뢰도 등급을 매겨 두었다.

| Group | 건수 |
|---|---:|
| G1 | 7,746 |
| G2 | 235 |
| G3 | 1,182 |
| G4 | 183 |
| G5 | 636 |

G1은 단일 출처(7,746건, `Ocurrences=1`·`SD=0`과 일치)다. 즉 **교차 검증되지 않은 라벨**이다.

### 제안하는 추가 실험

> 신뢰도 등급별로 테스트 성능을 나눠 보고한다.

- 가설: 라벨 신뢰도가 높은 구간(복수 출처 합의)에서 모델 성능이 더 좋게 나온다
- 만약 그렇다면, 전체 RMSE는 **라벨 품질과 모델 성능이 섞인 값**이라는 뜻이다
- 공수: 적다. 이미 있는 컬럼으로 테스트셋을 쪼개 집계만 하면 된다

비용 대비 신호가 가장 좋은 추가 실험이다. **라벨 예산 축(주 실험)을 흐리지 않으면서** 데이터 품질 감각을 보여준다.

### 발견한 문제

라벨 예산 스윕에서 학습셋을 100개로 줄이면, 양성 개수가 다음과 같이 된다 (train 80% 기준).

| 과제 | 예산 100의 양성 | 판정 |
|---|---:|---|
| SR-ARE (16.15%) | 약 16 | ❌ |
| NR-AhR (11.73%) | 약 12 | ❌ |
| NR-AR (4.25%) | 약 **4** | ❌❌ |

**양성 20개 미만에서 AUPRC는 사실상 무작위 수준으로 요동친다.** 이 상태로 "사전학습이 저데이터에서 유효한가"를 측정하면, 측정하고 있는 것이 모델 차이가 아니라 샘플링 운이 된다.

### 결정

| 항목 | 값 |
|---|---|
| 주 분류 과제 | **`SR-ARE`** (12과제 중 가장 균형적, 유효 건수 충분) |
| 분류 예산 사다리 | **`[300, 1000, 3000, None]`** — 100 제외 |
| 회귀 예산 사다리 | `[100, 300, 1000, 3000, None]` — 그대로 |
| 추가 안전장치 | 서브샘플 결과 양성 20개 미만이면 경고 + 결과에 플래그 |

> 기존 스펙은 `NR-AR`을 기본 과제로 두고 있었다. 양성률 4.25%로 12과제 중 네 번째로
> 불균형한 과제이며, 저데이터 실험에 가장 부적합한 선택이었다. **잘못된 기본값이었다.**

## 12. 재현 방법

이 문서의 모든 수치는 `scripts/audit_dataset.py`로 재현되어야 한다.

```bash
python scripts/audit_dataset.py --dataset aqsoldb --out docs/audit_aqsoldb.md
python scripts/audit_dataset.py --dataset tox21   --out docs/audit_tox21.md
```

- 문서의 숫자와 스크립트 출력이 어긋나면 **스크립트 쪽을 신뢰**하고 문서를 고친다
- `tests/test_audit_reproduces_numbers.py`로 정책 A/B 비교 수치를 고정한다

### ⏳ 남은 숙제

**Tox21에 염 처리 감사를 아직 돌리지 않았다.** 독성은 활성이 보통 모분자가 결정하므로 염 제거가 통례지만, AqSolDB에서 드러난 것과 같은 인공 중복이 생기는지 **데이터로 확인해야 한다.** 1주차 작업 순서 10번 항목이다.
